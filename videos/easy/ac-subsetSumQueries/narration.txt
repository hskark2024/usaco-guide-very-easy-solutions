Hey everyone. Today we are solving Subset Sum Queries from AtCoder and the USACO Guide Easy list. This problem takes the familiar subset-sum table and makes it dynamic: balls enter and leave a box, and after every change we count the subsets whose values add to a target K.

Every ball is distinguishable. If two balls both show the number two, choosing the red two and choosing the blue two are different subsets. Our answer is taken modulo nine hundred ninety-eight million, two hundred forty-four thousand, three hundred fifty-three.

Let ways of s be the number of subsets of the balls currently in the box whose sum is s. We only need sums from zero through K. At the beginning the box is empty, so ways of zero is one for the empty subset, and every positive sum has count zero.

Suppose we add a ball with value x. A subset totaling s either skips the new ball, which is already counted in ways of s, or takes it. If it takes the ball, removing that ball leaves an old subset totaling s minus x. So we add ways of s minus x into ways of s.

We must scan s downward from K to x. That direction ensures ways of s minus x still comes from before this new ball was added. If we scanned upward, a state made with the new ball could be used again later in the same query. We would pretend one physical ball was available several times.

Removal looks surprising, but it is the exact reverse. Call the array before removal old and the desired array after removal new. When the ball was added, old of s became new of s plus new of s minus x. Rearrange that equation: new of s equals old of s minus new of s minus x.

This time we scan upward. At sum s, the smaller entry new of s minus x has already been recovered. We subtract it from the current entry and add the modulus if the result is negative.

Here is a tiny trace. Let K equal five. Add a two; no subset reaches five. Add a three; the old subset containing two combines with the new three, so the answer becomes one. Remove the two. During the upward recovery, the contribution from two plus three is subtracted, and the answer returns to zero.

Equal values work without special handling. If three separate balls each have value two and K is four, there are three pairs after the third addition. The DP produces that count because each addition represents a new distinguishable choice. Removing one copy reverses exactly one factor and leaves one pair among the two remaining balls.

A value larger than K can be skipped. All values are positive, so such a ball cannot belong to a subset totaling K. We still print the answer after that operation.

For correctness, the addition cases, excluding or including the new ball, are disjoint and cover every subset. The descending loop uses the ball once. The removal equation algebraically reverses every coefficient, and the ascending loop supplies each already recovered smaller coefficient. Therefore ways of K is correct after every query.

Each query visits at most K states, so the running time is O of Q times K. The array uses O of K memory. With Q and K both at most five thousand, this fits the limits.
