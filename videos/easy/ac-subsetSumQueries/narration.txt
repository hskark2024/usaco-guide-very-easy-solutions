Hey everyone. Today we are solving Subset Sum Queries from AtCoder and the current USACO Guide Easy list. This problem starts like ordinary subset sum, then adds a twist: balls enter and leave the box, and we must answer after every change.

Each ball has a positive number. A plus query inserts one physical ball. A minus query removes one existing ball with that value. After the query, we count subsets whose values add to K. Equal-valued balls are still separate objects, so choosing the first five and choosing the second five are different subsets.

Our state is ways of s: the number of subsets of the balls currently present that sum to s. We only store sums from zero through K. The empty subset gives ways of zero equals one.

First, consider adding a ball worth x. Every new subset totaling s has two possibilities. It skips the new ball, which contributes the old ways of s, or it uses the new ball, which contributes the old ways of s minus x. So we add ways of s minus x into ways of s.

The scan direction matters. We move from K down to x. Then the source cell still describes subsets from before this ball was added. If we moved upward, a state created with this ball could be used again later in the same query, which would pretend one ball exists many times.

Removing a ball looks harder, but the addition equation tells us exactly how to reverse it. Call the table with the ball old and the table after removing it new. Addition said old of s equals new of s plus new of s minus x. Rearranging gives new of s equals old of s minus new of s minus x.

Now we must scan upward from x to K. When we reach s, the smaller new state at s minus x has already been recovered. Subtract it and normalize modulo nine hundred ninety-eight million, two hundred forty-four thousand, three hundred fifty-three.

Let us trace target ten. Add five: no target subset yet. Add another five: there are now two distinguishable balls, and choosing both makes ten, so the answer is one. Add ten: the single ten gives another subset, raising the answer to two. Remove one five: the pair of fives disappears, but the ten remains, so the answer returns to one.

What if x is larger than K? Because every value is positive, that ball can never appear in a subset totaling K. We still accept the query, but the stored table does not change. This is why truncating the array at K is safe.

For correctness, the addition step partitions every subset by whether it contains the new ball. Those two groups cannot overlap and cover every possibility. The removal step algebraically inverts that exact transformation, and its upward order guarantees each needed recovered value is ready. Therefore ways of K is correct after every query.

The C plus plus code stores the table in integers, performs one loop per relevant query, and prints ways of K immediately. The running time is O of Q times K and memory is O of K.

An important edge case is duplicate values. We do not track ball identities in the array, but the counting transition still treats every insertion as a new choice. Two fives double the choice paths correctly. Removing one applies one inverse factor and leaves the other one represented.
