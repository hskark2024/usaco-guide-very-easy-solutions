Hey everyone. Today we are solving Money Sums from CSES and the current USACO Guide Easy list. Instead of asking whether one target is possible, this problem asks us to print every positive total we can build.

We receive N physical coins. Each coin may be chosen zero or one time. Two coins can have the same value, but they are still two separate objects and can both be used.

Let maximum sum be the total value of all coins. No subset can produce anything larger. Create a boolean array reachable from zero through maximum sum. Reachable of s tells us whether some subset of processed coins totals s. Initially only zero is true because the empty subset makes zero.

Now process one coin worth c. Any sum that was already reachable stays reachable by skipping this coin. Also, if s minus c was reachable using earlier coins, then s becomes reachable by adding the current coin.

We update in place, so we scan from maximum sum down to c. That downward order is the whole zero-one rule. The source at s minus c has not yet been changed by this coin. An upward scan would let a newly reached total create another total during the same pass, reusing one physical coin again and again.

Take coins two, three, and five. Start with zero. After coin two, totals zero and two are reachable. After coin three, zero, two, three, and five are reachable. After coin five, we keep those totals and also reach five, seven, eight, and ten. The positive output is two, three, five, seven, eight, and ten.

Now look at duplicate coins two and two. The first coin reaches two. The second coin can read that earlier two and reach four. This is correct because there really are two physical coins. One pass cannot use a single two twice, but two separate passes may use both.

When every coin has been processed, scan the boolean array from one upward. Collect every true index. This automatically sorts the answers. Print the count first and the values on the next line.

For correctness, maintain this invariant: after processing the first i coins, reachable of s is true exactly when a subset of those i coins has sum s. The base case with zero coins is correct. For the next coin, any valid subset either excludes it and was already represented, or includes it and becomes an earlier subset for s minus c after we remove that coin. The downward scan ensures the earlier subset cannot already contain the current coin. Therefore the invariant holds, and the final true cells are exactly all possible totals.

The C plus plus code first sums the coin values to size the array tightly. It uses a compact char vector instead of a vector of booleans, then performs one descending loop for each coin.

The running time is O of N times S, where S is the total coin value. The memory is O of S. Under the official limits, S is at most one hundred thousand, so this is comfortably fast.

Check a one-coin case with value seven. The output count is one and the list contains seven. Check coins five and ten. Reachable totals are five, ten, and fifteen, with gaps everywhere else. The algorithm never assumes totals form a continuous interval.
