Hey everyone. Today we are solving Money Sums from CSES and the USACO Guide Easy list. We receive several physical coins and need to list every positive amount we can make by choosing a subset. Each coin may be used at most once.

This is a decision version of zero-one knapsack. Instead of maximizing pages or counting arrangements, each state stores a yes-or-no answer: can some subset make this sum?

First, add all coin values to get S. No subset can total less than zero or more than S, so our array needs positions zero through S. Let reachable of sum be true when a subset of the processed coins makes that sum.

Before reading any coin into the DP, reachable of zero is true. The empty subset makes zero. Every positive sum is false.

Now take one physical coin with value c. Every old subset totaling t can stay as it is, and it can also include the new coin to make t plus c. In array form, for every sum at least c, if reachable of sum minus c is true, mark reachable of sum true.

The loop scans from the total downward. This is the most important implementation detail. A smaller state cannot have been changed by the current coin yet when we read it. Therefore the new state uses this coin exactly once.

If we scanned upward, one coin valued two would first make sum two. Later in the same pass, that new sum two would make sum four, then sum six, pretending that we owned unlimited copies. Downward order prevents that chain.

Trace the official sample with coins four, two, five, and two. Start with zero. After the four, we can make four. After the first two, we can make two, four, and six. The five adds five, seven, nine, and eleven. The final two is a separate physical coin, so it can combine with subsets that used the first two.

At the end, the positive reachable sums are two, four, five, six, seven, eight, nine, eleven, and thirteen. There are nine of them. We scan the array from one upward, so they automatically appear in increasing order.

Duplicate values deserve attention. The two coins labeled two are separate items. We may choose neither, either one, or both. Our algorithm processes them in separate iterations, so using both is allowed while using either physical coin twice is not.

For correctness, use induction on processed coins. With no coins, only zero is possible. For the next coin, every subset either excludes it, leaving an already reachable sum, or includes it. Removing the coin from the second case leaves an earlier subset totaling sum minus c. Our transition marks exactly those possibilities. Descending order ensures the source uses only earlier coins. So the invariant remains true.

After all coins, every true positive position is a possible money sum, and every possible sum is true. We collect those positions into a vector and print its size and contents.

The running time is O of N times S, where S is the sum of all values. Memory is O of S. Here N is at most one hundred and S is at most one hundred thousand, so the method easily fits.

The C plus plus code uses a vector of char values for compact boolean storage. It accumulates the total while reading, performs one downward loop per coin, and then prints the sorted results.
