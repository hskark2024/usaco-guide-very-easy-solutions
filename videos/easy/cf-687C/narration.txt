Welcome! Today we are solving The Values You Can Make, Codeforces problem six eighty seven C. We have physical coins and need to pay exactly K. For every possible payment, imagine marking some of the coins inside it. We want all amounts the marked coins can add to. The payment can change between answers, so we must explore every valid payment rather than choose just one.

A normal subset sum tracks one total. Here we need two: the full payment total and the marked total inside that payment. Let possible of P and X mean that a payment totaling P exists and some subset inside it totals X. The beginning state is zero, zero: an empty payment with an empty marked subset. A marked coin must always belong to the payment.

For each new coin with value V, there are exactly three roles. First, leave it outside the payment, which keeps both totals. Second, put it in the payment but do not mark it, which adds V only to the payment. Third, put it in the payment and mark it, which adds V to both totals. There is no fourth role where a marked coin sits outside the payment.

We compress the horizontal dimension with a bitset. For a fixed payment total P, bit X says whether inside sum X is possible. Copying a source row adds the coin only to the payment. Shifting the same source row left by V adds V to every inside sum too. We combine these choices with bitwise OR. The existing destination row already represents skipping the coin.

Now process payment totals from K downward to V. The source row P minus V has not been changed by this coin yet. That means every transition uses this physical coin once. An upward scan could consume a state that already used the coin and then use it again. Equal-valued coins remain separate items because each one gets its own downward pass.

Try coins two and three, with payment target five. Both coins must be selected for this payment. The marked subset can be empty, only two, only three, or both. The inside sums are zero, two, three, and five. Notice that one and four are ordinary numbers below five but cannot be made from these coins. We read only the row whose payment total equals five.

Another official example uses coins twenty five, twenty five, and fifty with target fifty. One payment uses the fifty coin and another uses both twenty five coins. Across those choices, the inside sums are zero, twenty five, and fifty. Duplicates are real coins, so we keep both passes. A coin larger than K can be ignored because all values are positive. Whenever a payment exists, zero and K are valid answers.

In C plus plus, create K plus one rows of bitset five hundred and one, since K is at most five hundred. Set bit zero in row zero. For every coin, scan payment totals downward and combine the source row with its shifted copy. Finally collect the set bits from zero through K in the last row, print their count, and print them in ascending order. Bitsets process many inside sums in each machine operation. We verified small cases by assigning every coin one of the three roles directly, and checked maximum-size cases too. The key lesson is to define both totals clearly and derive transitions from the legal roles of one coin.
